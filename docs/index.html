如何使用

需要 Python 3.9+，无需安装第三方依赖。把两个文件放在同一目录，在该目录执行：

python3 plot_pareto.py pareto_example.csv --output points.json

然后将 points.json 导入本页。采集真实数据时，将示例替换为自己的压测结果，并记录并行方式、GPU 数和 Prefill chunk 配置。

    稳态理论 · 无排队假设

    先在延迟预算内分别选择 P、D 单卡吞吐最高的实测点，再用输入/输出长度换算请求处理能力，匹配 GPU 与实例数量。使用同一 workload 的全部导入点；下方曲线勾选只影响图表。

    容量余量、整数配比与完整请求时间

    Prefill 延迟预算 = TTFT − 延迟预留。预留用于实际首 token 路径上的排队、合批、路由或传输；不会自动增加一个 TPOT，也不预测排队时延。按采样的延迟统计口径筛选，均值不能用来证明 P95/P99 达标。

    P 容量余量 20% 表示仅用测得容量的 80% 做配比。基础配比须让 P 可用容量覆盖 D，再在富余容差内选择 GPU 数最少的整数实例组合；找不到时显示原因。目标 QPS 填写后，分别向上取整 P、D 数量，基础配比搜索上限不限制目标部署。

    输入/输出长度、模型、精度、硬件、上下文和缓存条件必须与采样 workload 一致。这里按测得吞吐换算 requests/s，不将 GPU 性能外推到新长度；单卡吞吐分别按 P、D 实例各自的 GPU 数归一化。

    优先使用逐点 prefill_service_ms，其次使用按配置补充的完整请求时间。以上确认仅适用于 chunk=false 且横轴为单步延迟的点；chunk 单步时间及含排队的 TTFT 均不自动代入。完整请求时间覆盖全部 chunks、排除调度等待；配置校准仅补充缺失点。

    导入同一 workload 的 Prefill 与 Decode 点位后开始。默认参数仅用于合成示例，请换成实际业务参数。
